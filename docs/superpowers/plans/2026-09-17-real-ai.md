# KIDSPPT 真实 AI 接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不打开真实支付的前提下，为 KIDSPPT 接入受预算、用量和输出校验保护的 DashScope 多模态生成，并保留当前微信登录、队列、前 5 页免费和 PPT 排版流程。

**Architecture:** 新增无第三方依赖的 `server/ai.mjs`，使用 Node 原生 `fetch` 调用 DashScope OpenAI-compatible Chat Completions。Worker 在真实模型调用前通过现有 `CostControl` 预留预算，成功后按 provider usage 结算；模型输出先解析为结构化 slides，再通过现有 `validateSlides`，任何 provider 失败或无效输出都 fail closed，不回退到 demo。

**Tech Stack:** Node.js 24+、原生 `fetch`、SQLite、现有 `CostControl`、PptxGenJS、Node test runner、现有 Playwright UI 测试。

**Spec:** `docs/superpowers/specs/2026-09-17-real-ai-design.md`

## Global Constraints

- `APP_MODE=live` 和真实微信登录保持不变。
- `PAYMENT_MODE=disabled` 保持不变；不实现或打开微信支付、支付宝、退款和支付回调。
- `AI_MODE=demo` 的本地演示行为必须保持可用；只有明确配置 `AI_MODE=qwen` 才调用 provider。
- `AI_MODE=qwen` 缺少 API Key、Base URL、模型、最大 token 或输入/输出价格时必须 fail closed。
- 正式试运营每个微信账号每天最多新建 1 份作品，按北京时间计日。
- 免费阶段最多发送前 8 张照片；照片只从服务器私有文件读取，不生成公开图片 URL。
- API Key、AppSecret、图片 Base64、完整 prompt、模型响应正文和真实用户素材不得进入源码、部署包、接口响应或普通日志。
- 不新增 OpenAI SDK 或其他 provider 依赖；使用现有 Node 原生 `fetch`。
- 项目目录不是 Git 仓库；每个任务以测试和工作区差异作为 checkpoint，不执行 `git commit`。

> 2026-09-17 协议校正：百炼官方结构化输出文档将 Qwen3-VL-Plus 列为非思考 `json_object` 支持模型，而非 JSON Schema 支持模型。实际实现改为 `enable_thinking=false` + `json_object` + 本地严格校验，并以 `max_tokens` 限制输出；原任务中的 JSON Schema 表述不再作为生产协议。

## Completion Criteria

- `npm test` and `npm run test:ui` pass after the changes.
- The synthetic qwen path is covered by tests for success, invalid output, provider failure, timeout, missing usage and budget refusal.
- Demo mode and existing local UI behavior remain available.
- The production process can be configured with `AI_MODE=qwen` only when all required AI settings are present; payment remains disabled.
- A controlled real call has fresh evidence for model response, usage, cost settlement, output validation and PPT generation.
- No real secret is present in the workspace, documentation, or deployment package.

## Checkpoint and Rollback

- Before deploying, copy the existing production env file to a protected server-side backup outside the deployment zip; never print it or commit it.
- Rollback is `AI_MODE=demo` plus application restart; keep `PAYMENT_MODE=disabled` and do not run `docker compose down -v`.
- If usage is missing or provider billing is uncertain, keep the budget reservation held and mark the task failed/unknown for manual review.
