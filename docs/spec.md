## 3. 建议的首版体验

1. 家长通过微信登录，进入制作页。
2. 上传图片，填写年级、性别、演示稿描述并选择风格。
3. 默认直接生成；只有勾选“先编辑内容大纲”才进入编辑确认。
4. 服务端异步生成作品，显示实际阶段：排队、整理内容、排版、导出、完成或失败。
5. 作品页展示前 5 页清晰预览，其余页显示标题和锁定状态。
6. 家长选择“免费下载前5页”或“完整PPT ¥50”。
7. 已购买作品进入“我的作品”，可再次下载；订单页显示实际支付及交付状态。

首版页面：制作、内容确认、生成进度、作品预览、我的作品、订单与隐私设置。作品卡片显示主题、创建时间、页数和状态。

建议默认 12 页，可选择 5 至 20 页；以内容充足程度调整，不靠重复内容凑页。若作品总共不超过 5 页，按前 5 页免费规则提供完整免费下载，不展示付费按钮。此页数范围和边界处理待随方案确认。

## 4. 内容与排版

- 根据年级和演示目的组织主题与语言；无需每页使用第一人称，知识介绍直接讲内容，个人感想才使用个人视角。
- 禁止重复“我先完成了”“我认真听、认真看”等空泛句式。本地模式仅提取与整理已有文字；真实AI服务接通后才提供模型润色，不混淆两者。
- 完整分页讲稿保留章节和顺序，页面使用简要文字，完整原稿保留在讲者备注；时长、页码和主持提示不当成活动事实。
- 性别用于家长提供的角色设定，不推断性格、能力或兴趣，也不从照片识别孩子身份。
- 活动事实以家长在合并文本框中填写的内容及确认过的图片说明为准，不编造学校、人物、日期、现场对话、实验结果或获奖经历。
- 感想作为待家长确认的写作草稿，不把模型拟写的情绪当作孩子真实表达。
- 活动汇报建议结构：封面、活动简介、过程、亮点、收获、结束；其他类型使用对应结构。
- PPT 输出为 `.pptx`，文字和图片可编辑。采用 16:9 固定版式，首版提供清新自然、活力童趣、简洁汇报三个模板。
- 长文优先拆页、精简句子，不无限缩小字号；照片保留比例，关键主体不被随意裁掉。
- 首版不增加会员、积分、裂变邀请、模板商城等额外商业模块。

## 5. 下载和订单规则

以下为推荐实现，需要随首版方案确认：

- 50 元购买某一份确定版本的完整文件下载权。同一账号重复下载同一版本不重复收费。
- 免费版和完整版分别导出。免费包内只含前 5 页需要的内容与媒体，不将后续页藏在文件、备注或附件中。
- 服务端固定售价为 `5000` 分、币种为 `CNY`；客户端传来的金额不能改变订单价格。
- 新作品前5页生成成功后，先预留交付预算再允许下单；确认付款后补全后续页。付费失败显示交付异常待处理，真实退款机制接入前不得正式收款。
- 下载地址由服务端核对账号、作品归属、有效购买记录后短时签发。猜测文件地址或修改前端状态不能解锁完整文件。
- 支付渠道的服务端通知或可信查单结果确认成功后，事务性写入订单和下载权益。校验订单号、商户身份、金额、币种及订单关联的购买者；重复通知只发放一次权益。
- 支付取消保持未支付；结果未明显示处理中并查单，不能要求用户立刻再次付款。
- 技术故障重新导出同一版本不再次收费。修改内容后形成新版本，若要另收费，必须在重新生成或购买前明确提示；旧版本下载权保留。
- 退款、交付失败补偿和文件保存期限须在正式收费前确定，并与实际支付渠道规则一致。

## 6. 技术路线比较

| 路线 | 取舍 |
| --- | --- |
| 微信原生小程序 + 独立 Node.js 服务及生成进程 | 推荐。直接围绕微信交互开发；后台能独立处理图片、异步任务、PPT 导出及支付 |
| uni-app + 独立后端 | 适合已经明确要同时支持 H5 或 App 的情况，首版需承担额外跨端适配 |
| 低代码界面 + 第三方整套 PPT 生成服务 | 起步可能更快，但需要另外核实可编辑性、模板质量、图片处理、数据留存及供应商费用 |

推荐架构：微信原生小程序负责交互；Node.js/TypeScript API 负责账号、作品和订单；后台任务进程负责图片处理、模型调用、模板排版及导出；数据库保存任务和权益；私有对象存储保存图片和输出文件。

生成模块建议用 PptxGenJS 输出 `.pptx`。该库官方文档确认支持 Node.js、文本、图片及 PowerPoint 文件导出。预览渲染需要另外配置渲染工具，不能假定该库同时生成页面截图。

首版可将 API 和生成进程部署在同一服务环境，用数据库保存可恢复的任务；不为初期流量额外引入复杂消息中间件。AI 供应商在确认图片使用及留存条件后选择。

核心记录：家长账号、作品、输入素材、不可变作品版本、生成任务、输出文件、订单、下载权益。价格、作品归属和购买状态均以服务端数据为准。

## 7. 隐私与运行设计

- 上传前向家长说明图片及文字的用途、实际处理服务商、保存期限和删除方法。
- 默认不收集学校、班级、家庭地址等额外资料，封面姓名使用家长主动输入的昵称。
- 原图、预览、PPT 均按账号隔离，私有保存；下载链接短时有效。
- 图片上传后检查真实格式、大小与像素尺寸，并清除位置等不必要的 EXIF 元数据。
- 支持删除作品及其原图、预览和导出文件；订单保留要求与作品素材删除分开设计。
- 生成失败不收费，可恢复的任务允许有限重试。账号生成次数和并发数设置服务端可配置上限，具体额度上线前结合模型成本确定。
- 外部 AI、云资源和真实支付未配置时，开发演示明确显示模拟状态，不能标为真实生成或真实付款。

## 8. 验收标准

1. 五项指定参数缺失时无法提交；自定义类型必须有名称；服务端同样校验输入。
2. 图片顺序和活动流程可调整，模型生成大纲可被家长修改。
3. 三年级男孩等角色参数实际影响语言难度；正文有自然扩写和孩子第一人称表达，没有资料支持的事实不自行补全。
4. 生成的 PPT 能在 PowerPoint/WPS 打开，图文可编辑，中文、长标题、横竖图片不重叠溢出。
5. 免费文件实际最多 5 页；解包检查不能找到第 6 页及其专属文字、备注和媒体。
6. 未支付、其他账号、过期链接均不能下载完整版；前端篡改价格和支付状态无效。
7. 支付取消、重复通知、延迟通知、查单恢复和金额不符均有覆盖；只在可信支付成功后发放一次权益。
8. 同一版本重下、下载中断后重试均不重复收费；未生成成功的作品不能下单。
9. 微信开发者工具及 iOS/Android 真机验证图片上传、文档打开、下载或转发能力。未实测的平台分别记录，不能以浏览器原型替代小程序验收。
10. 作品删除、跨账号隔离、任务进程重启恢复经过验证。

## 9. 实施顺序与外部依赖

1. 首先实现本地生成模块：输入校验、大纲、模板、完整与前 5 页文件导出，使用合成或已授权素材验证。
2. 完成小程序页面、私有上传、异步任务、作品列表和下载鉴权，验证端到端使用流程。
3. 在测试环境接入真实 AI 和适用的支付渠道，验证订单、回调、交付和退款流程，再准备正式发布。

接入阶段需要核实：小程序主体和 AppID、可用服务类目及支付产品、商户配置、部署区域和域名、AI 服务商，以及 iOS 和 Android 对该付费内容的实际支持。不要在聊天或小程序代码中放置密钥。

微信数字内容支付及 iOS 接入官方页面本次读取失败，尚不能确认适用渠道、开通条件或费率。已读取的一般小程序支付文档可支持服务端验签、查单及幂等处理设计，但不代表本产品已获准使用该支付产品。
